# ClauseLab Architectural & Consensus Design

## 1. Executive Summary & Core Pitch
Ambiguity in an agreement normally reveals itself only after a dispute has already emerged—when validators split, payments freeze, and counterparty trust breaks down. **ClauseLab** surfaces ambiguity **before signing**:
1. Each party contributes concrete, hypothetical scenarios tagged with their expected outcome (`labels`).
2. Validator consensus rules on each scenario under GenLayer's Equivalence Principle.
3. Any scenario where consensus disagrees with the expected outcome (or returns `UNDECIDABLE`) flags the clause as ambiguous (a red scenario).
4. The clause can only be **LOCKED** when every scenario is green, each party has proposed at least one scenario, and all parties have signed.
5. At dispute time, the locked scenarios act as:
   - **Anchors**: Few-shot exemplars embedded into the prompt, grounding the LLM in settled mutual intent.
   - **In-Band Canary**: One held-back settled scenario is re-evaluated in the exact same consensus round as the disputed facts. If the validator model errs on the known scenario, the ruling is flagged as `UNRELIABLE` (the judge abstains) rather than issuing a confidently incorrect verdict.

Non-goals: ClauseLab holds no funds and acts as no escrow. It interprets legal/technical clauses against facts the parties mutually stipulate, without verifying raw external world truth.

## 2. Validator Consensus Design: Why Compare What We Compare

```
+-------------------------------------------------------------------------------+
| Consensus Operation | Return Type | What Validators Compare | Why Compare?    |
+---------------------+-------------+-------------------------+-----------------+
| run_scenario        | str (label) | Exact enum label string | gl.eq_principle |
|                     |             | e.g. "DELIVERED"        | .strict_eq      |
+---------------------+-------------+-------------------------+-----------------+
| adjudicate          | str (enum)  | "VERDICT|1" or          | Binary verdict  |
|                     |             | "UNRELIABLE|0"          | + canary pass   |
+---------------------+-------------+-------------------------+-----------------+
```

### Why Strict Equivalence on Decision Fields Only?
In GenLayer, validators re-execute contract methods in sandboxed GenVM instances. Natural language explanations generated by Large Language Models vary across temperatures, seed differences, and provider versions.
If a consensus method returns free-form text or rationale (e.g. `{"verdict": "BREACH", "reason": "The delivery occurred on Monday..."}`), validators will disagree on the syntactic explanation even when they agree on the legal verdict.

Therefore, **both consensus calls in ClauseLab return a single canonical string**:
- `run_scenario` returns only the canonical label string (e.g. `DELIVERED`, `BREACH`, or `UNDECIDABLE`).
- `adjudicate` returns `VERDICT|CANARY_PASS` (e.g. `DELIVERED|1` or `UNRELIABLE|0`).

Every validator deterministically selects the identical anchors and the identical canary scenario, executes inference inside the non-deterministic block, parses the JSON payload, normalizes the label via code, and compares the resulting canonical string.

## 3. In-Band Canary Calibration & Anchoring

### Deterministic Anchor Selection
Anchors provide few-shot calibration to the model. Up to 3 scenarios with distinct expected labels are selected deterministically by scenario index:
```python
def _anchor_ids(scenarios):
    seen, out = [], []
    for sc in sorted(scenarios, key=lambda x: x["n"]):
        if sc["expected"] not in seen and len(out) < 3:
            seen.append(sc["expected"])
            out.append(sc["n"])
    return out
```

### Canary Selection
The canary scenario must be **disjoint** from the anchors. It is chosen via a deterministic pseudo-random hash over the immutable `spec_hash` and the `facts_hash`:
```python
def _canary_id(spec_hash, facts_hash, scenarios):
    anchors = _anchor_ids(scenarios)
    cands = sorted([sc["n"] for sc in scenarios if sc["n"] not in anchors])
    if not cands:
        return None
    return cands[int(_sha(spec_hash + facts_hash)[:8], 16) % len(cands)]
```
Because `spec_hash` is locked on-chain and `facts_hash` is computed from the stipulated facts text, every validator independently selects the exact same canary scenario without cross-node network calls.

### In-Band Evaluation
During `adjudicate`:
1. The validator first prompts the model on the held-back canary scenario with the anchors.
2. The validator prompts the model on the disputed facts.
3. If the model's answer on the canary does not match `canary["expected"]`, the output verdict is replaced by `"UNRELIABLE"` and the canary flag is set to `0`.
4. Downstream consumer contracts or human escalation policies detect `UNRELIABLE` and abort automated execution.

## 4. Storage Architecture

To prevent storage serialization bugs or integer-type mismatch issues across GenVM releases, **all storage collections use `TreeMap[str, str]` holding canonical JSON strings**.

### Collections
1. `specs: TreeMap[str, str]`
   - Key: `spec_id` (12 hex characters)
   - Value:
     ```json
     {
       "schema_version": "1.0",
       "spec_id": "b839e9f46515",
       "author": "0x74b667c1ed58c4eebfaf964f87a12c35c49261db",
       "title": "Software Delivery Agreement",
       "clause": "The contractor shall deliver...",
       "labels": ["DELIVERED", "BREACH"],
       "version": 1,
       "status": "DRAFT",
       "parties": ["0x74b667c1ed58c4eebfaf964f87a12c35c49261db"],
       "signed": [],
       "n_scenarios": 4,
       "spec_hash": "a4f89d..."
     }
     ```

2. `scenarios: TreeMap[str, str]`
   - Key: `"spec_id:n"` (e.g. `"b839e9f46515:1"`)
   - Value:
     ```json
     {
       "schema_version": "1.0",
       "spec_id": "b839e9f46515",
       "n": 1,
       "text": "Contractor delivers on day 2.",
       "expected": "DELIVERED",
       "proposer": "0x74b667c1ed58c4eebfaf964f87a12c35c49261db",
       "ran_version": 1,
       "label": "DELIVERED",
       "matches": true
     }
     ```

3. `facts: TreeMap[str, str]`
   - Key: `"spec_id:facts_id"`
   - Value:
     ```json
     {
       "schema_version": "1.0",
       "spec_id": "b839e9f46515",
       "facts_id": "c194ea720b12",
       "text": "The repository was delivered on day 3 with passing tests.",
       "by": ["0x74b6...", "0x89c1..."]
     }
     ```

4. `rulings: TreeMap[str, str]`
   - Key: `"spec_id:facts_id"`
   - Value:
     ```json
     {
       "schema_version": "1.0",
       "spec_id": "b839e9f46515",
       "facts_id": "c194ea720b12",
       "verdict": "DELIVERED",
       "canary_pass": true,
       "spec_hash": "a4f89d..."
     }
     ```

5. Discovery Indexes:
   - `party_specs: TreeMap[str, str]`: maps lowercase party address to JSON array of `spec_id`s (capped at 20).
   - `latest_spec: TreeMap[str, str]`: maps lowercase author address to latest `spec_id`.
   - `spec_facts: TreeMap[str, str]`: maps `spec_id` to JSON array of `facts_id`s.
   - `latest_facts: TreeMap[str, str]`: maps `spec_id` to latest `facts_id`.

## 5. Security & Prompt Containment

All user-supplied text (scenarios and stipulated facts) is untrusted user data.
1. Bounded byte lengths are strictly enforced before storage (`clause <= 2000`, `title <= 200`, `scenario <= 600`, `facts <= 1500`).
2. Input text is wrapped in `<UNTRUSTED_CASE>...</UNTRUSTED_CASE>` delimiters.
3. System prompts explicitly instruct the model that everything within the delimiter is raw data, never instructions.
4. Output is required to be JSON, parsed with regex/fence stripping, and sanitized via `_clean_label`: any label not in the spec's whitelisted labels list immediately defaults to `UNDECIDABLE`.

---

## 6. Honest Limitations
1. **Canary as a Signal, Not a Proof**: One held-back canary scenario provides an in-band sanity check against gross drift or hallucination, but does not guarantee the model will correctly reason about all subtle nuances in the disputed facts.
2. **Anchor Bias**: While few-shot settled examples dramatically increase cross-validator reproducibility, they can introduce subtle inductive bias if chosen scenarios lean disproportionately toward one interpretation.
3. **No External Fact Finding**: ClauseLab adjudicates solely on what the parties mutually stipulate and confirm. It does not pull live APIs or confirm whether real-world delivery actually occurred.
